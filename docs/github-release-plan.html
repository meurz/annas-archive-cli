Proposal · 12 September 2026 · No migration executed

Make each GitHub CLI easy to run, test, release, and maintain.

Adopt GitHub as the canonical host for projects explicitly designated for GitHub. Use English project content, publish a Python package for one-command execution, and provide standalone downloads for users without Python.

Recommended: retain the Python implementation; publish through PyPI and GitHub Releases; use GitHub Actions for pull-request checks and tagged releases. Establish this project as the first reference implementation, then extract a small reusable template.

The commands below are the intended post-publication interface. The package and installers are not published yet.

# Run without permanent installation (requires uv)
uvx --from annas-archive-cli anna search "Jane Austen"

# Install / upgrade permanently
uv tool install annas-archive-cli
uv tool upgrade annas-archive-cli

# Reproduce an exact version
uvx --from annas-archive-cli==0.2.0 anna --version

Standalone targets

Plan for Linux x86_64 / arm64, macOS arm64 / x86_64, and Windows x86_64. Use native builders and test each architecture. Confirm runner availability and cost before making these supported promises. Windows arm64 follows demonstrated demand.

Publish archives such as anna-v0.2.0-linux-x86_64.tar.gz and anna-v0.2.0-windows-x86_64.zip, including license notices.

Installer contract

Provide POSIX shell and PowerShell installers after the GitHub namespace is chosen. Detect OS/architecture, select the exact asset, verify SHA-256, install to a user directory and explain PATH changes. Allow version pinning and document upgrade/uninstall.

No administrative privilege by default. Offer a download-and-inspect path alongside the one-line installer. Hashes detect corruption; release provenance identifies the build. OS code signing remains separate.

For Linux, choose and test a minimum glibc version; PyInstaller does not produce a universally portable Linux binary. Do not promise Alpine/musl support without separate validation. macOS notarization and Windows signing require identities and possibly paid services; unsigned previews must document their installation behavior.
